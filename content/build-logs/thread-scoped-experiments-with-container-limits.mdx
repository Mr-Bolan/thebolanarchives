## current state

This implementation adapts an upstream agent and companion interface. It is documented
as separate from the earlier investigation workbench, not a completed integration or
a wholly original framework.

The experiment store reserves work by thread and call identity. Its fingerprint combines
the command, evaluation plan, and hashes of supplied input bytes. Reusing an identity
with different fingerprinted material raises an error instead of returning a stale
result. Reservation also checks remaining execution time, concurrent work in the same
thread, and saved-artifact capacity.

The container launcher requests no network, a read-only root filesystem, a non-root
user, dropped capabilities, and process, CPU, and memory limits. Bounded temporary
filesystems provide working space. These are concrete launch arguments, not an observed
containment result.

## limits

The SQL tools sit outside that experiment container boundary. The source documentation
explicitly says database account privileges determine access, including writes. A
restricted experiment process therefore does not make the entire research agent
read-only.

This is source review only, with runtime unverified. No container, database, model,
or attachment was opened or executed. Cancellation, replay recovery, output limits,
and isolation still need controlled tests before operational claims are warranted.
