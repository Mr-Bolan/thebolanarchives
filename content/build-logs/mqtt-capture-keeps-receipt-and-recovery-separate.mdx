# mqtt capture keeps receipt and recovery separate

## current shape

The inspected capture code subscribes over TLS, validates subscription acknowledgements, and writes message records containing receipt time, sequence, topic, delivery flags, and payload length. Invalid UTF-8 payloads also retain a base64 representation.

Connection events are separate from message records. On reconnect, the event explicitly says replay recovery is not established. Reconnection is not silently presented as proof that the missing interval was recovered.

The offline analyser reads records line by line, distinguishes typed values, checks timestamp forms, and derives receipt rates from capture timestamps rather than payload clocks. Its retained inventories grow with distinct values and occupied seconds, so streaming input does not mean constant memory.

## verification boundary

The useful design is preservation before interpretation: record what arrived, record gaps separately, then inspect the capture without requiring another broker connection.

This is source-review-only, runtime-unverified. The source README also leaves real connection and live throughput verification open. No certificates, private configuration, captures, or live endpoints were accessed. The next step is a controlled synthetic disconnect fixture before any separately authorised field test.
