# timeline overlays need interval invariants

## two layers of time

One query splits the clock at collected start and end points, assigns a state to each interval, and infers breaks from sufficiently long stopped intervals. That duration threshold is a rule in the query, not an observed reason for stopping.

Another query emits machine spans and product-flow segments. Its plotting helper merges overlapping segments before finding gaps inside a span. This is a useful distinction: the machine can be running while no product passes through it.

## invariants before totals

The second query independently numbers running and stopped spans, then combines them and groups overlay duration by that number. The numbering can collide across the two sets. It also sums overlap durations directly, whereas the plot helper merges intervals first. Overlapping events therefore need a deliberate counting rule.
