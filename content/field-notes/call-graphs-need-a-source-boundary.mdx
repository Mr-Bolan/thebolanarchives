# call graphs need a source boundary

## the wrapper's contribution

The inspected wrapper recursively collects Python files, asks an existing call-graph library for definition and use edges, writes a temporary DOT file, and invokes Graphviz for raster and vector output. A smaller companion generates DOT for the bundled analysis library itself.

The graph engine is upstream software. The local contribution is orchestration and output selection, not a new analysis algorithm.

## scope before layout

The recursive walk does not prune dependency environments or generated directories. A graph of every Python file under a folder can become a graph of installed dependencies rather than the application.

The useful next change would be an explicit source-root and exclusion contract, followed by a small fixture that demonstrates which files enter the graph. Visual density is not evidence of architectural complexity until that boundary is known.

This is source-review-only, runtime-unverified. The wrappers and rendering commands were not executed, and existing generated diagrams were not treated as evidence of successful current behaviour.
