## the mismatch

The helper's base query uses an inclusive start timestamp and exclusive end timestamp.
Without a schedule, those timestamps define the reporting interval.

With a schedule, it builds additional daily clauses. The date iterator stops before
the end date. For two timestamps on the same date, it produces no days at all. The
empty-clause branch then returns an always-false filter. A scheduled same-day interval
can therefore produce no rows even though the base timestamp range is nonempty.

There is a second boundary choice: work windows and breaks use inclusive SQL time
comparisons. A minute at a break's end remains excluded. Whether that is correct depends
on the reporting convention; the code alone cannot settle it.

## what this supports

This is a source-derived boundary finding, not a claim about an incorrect delivered
report. No source application or database was run, and runtime behavior is unverified.
The helper came from a downloaded tooling collection; its presence establishes neither
authorship nor deployment.

The smallest useful verification would cover a same-day window, a final partial day,
and minutes exactly at work and break boundaries using synthetic timestamps. Decide
the interval convention before comparing the resulting totals with a dashboard.
